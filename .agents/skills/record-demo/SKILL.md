# Skill: record-demo

Позволяет превратить выполнение консольного проекта в видеофайл (MP4) полностью
автоматически: команды «печатаются» сами, программа выполняется, результат
захватывается и рендерится в видео. Руками записывать экран не нужно.

## Пайплайн

```
demo-magic.sh  →  asciinema rec  →  agg
(имитация ввода)   (.cast поток)    (.mp4 видео)
```

## Предпосылки (инструменты)

Нужны: `asciinema`, `agg`, `pv`, `ffmpeg`. Проверить/установить:

```bash
make install-tools          # или вручную:
brew install asciinema agg ffmpeg pv
```

- `pv` — обязателен для реалистичной «печати» команд (demo-magic использует его).
- `agg` — рендерит `.cast` в MP4/WEBM/GIF.

## Шаги

### 1. Создать demo-скрипт для конкретного дня

```bash
make new-demo DAY=day_01
# эквивалентно:
.agents/skills/record-demo/scripts/new-demo.sh day_01
```

Это создаст `day_01/demo/demo.sh` (исполняемый, из шаблона).

### 2. Отредактировать команды в `day_01/demo/demo.sh`

Шаблон уже подключает `demo-magic.sh` и задаёт `DEMO_PROMPT`. Дополните команды.

Основные функции demo-magic:

| Выражение | Действие |
|-----------|----------|
| `p "# текст"` | напечатать комментарий (не выполняется) |
| `p "команда"` | напечатать команду (без выполнения) |
| `pe "команда"` | напечатать **и выполнить** |
| `pei "команда"` | выполнить сразу, без пауз |
| `wait` | пауза |
| `clear` | очистить терминал |

Полезные переменные:

- `DEMO_PROMPT` — строка приглашения (например `"➜ "`).
- `TYPE_SPEED` — скорость печати символов (по умолчанию 20).
- `PROMPT_TIMEOUT` — лимит ожидания между шагами (для автоматизации > 0).

> **Рекомендация для day_01:** используйте аргументный режим программы —
> `pe "go run . \"ответь 2 слова: жажду кодить\""` (короткий запрос = короткое
> видео). Это детерминированно и не ждёт ввода. Интерактивный ввод тоже можно
> показать (см. раздел ниже), но он требует аккуратности с TTY.

#### Как писать сценарий — только функции, без «воды»

Сценарий должен **фокусироваться на демонстрации возможностей программы**, а не
на служебных командах. Правила:

1. **Один-два шага «контекста» максимум** (например один `cd day_01`), чтобы было
   понятно, где мы. Не нужно `ls`, `cat`, `head`, `make build`, `pwd` и т.п.,
   если они не являются целью демонстрации.
2. **Главное — показать функцию программы**: реальный запуск с осмысленным вводом
   и её вывод. Всё остальное — только если это само по себе важно.
3. **Комментарии (`p "# ..."`) короткие и по делу**, без пересказа того, что и так
   видно на экране.
4. **Не добавляйте воду ради длины.** Видео должно быть коротким и сфокусированным.
   Лучше 15–30 секунд чистого прогона, чем минута с лишними командами.

Пример правильного сценария (демонстрирует именно функцию):

```bash
clear
p "# LLM-клиент: отправляем запрос и получаем ответ"
pe "go run . \"ответь 2 слова: жажду кодить\""
```

Если в рамках проекта есть несколько функций — покажите каждую одной командой,
а не обставляйте их лишними выводами.

### 3. Записать видео

```bash
make record DEMO=day_01/demo/demo.sh
# или напрямую (подробнее про флаги — в самом скрипте):
.agents/skills/record-demo/scripts/record-demo.sh day_01/demo/demo.sh
```

Что происходит внутри:
1. `asciinema rec day_01/demo/output.cast --overwrite -c "bash demo.sh -w 1"`
   — запускает demo-скрипт в псевдотерминале и пишет поток в `.cast`
   (флаг `-w 1` делает демо неинтерактивным: шаги идут с задержкой 1 с).
2. `agg day_01/demo/output.cast day_01/demo/output.mp4` — рендер в MP4.
3. Промежуточный `.cast` удаляется (если не задан `KEEP_CAST=1`).

Полученный файл: `day_01/demo/output.mp4`.

### 4. (Опционально) Открыть результат

```bash
open day_01/demo/output.mp4
```

## Интерактивный ввод в demo-скрипте

Если программа ждёт ввода (как `go run .` без аргумента), можно показать ввод так:

```bash
pe "go run ."
# затем «набрать» ответ — через echo в stdin либо pty:
# 1) без имитации печати:
#    printf 'Текст запроса\n' | go run .
# 2) с имитацией — запустить программу в фоне и подождать, затем передать ввод.
```

Проще и надёжнее для записи — всегда использовать аргументный режим, если
программа его поддерживает. Если интерактив обязателен, пишите команды так,
чтобы ввод шёл через `printf ... | ` (надёжно в неинтерактивном TTY).

## Кастомизация вывода

Через переменные окружения `record-demo.sh`:

```bash
AGG_OPTS="--theme=tango --fps 30" make record DEMO=day_01/demo/demo.sh
AGG_OPTS="--font-size 16" .agents/skills/record-demo/scripts/record-demo.sh day_01/demo/demo.sh day_01/demo/output.webm
```

Формат определяется расширением выходного файла (`.mp4`, `.webm`, `.gif`).

## Устранение неполадок

- **Видео полностью чёрное (текста не видно)** — дефолтная тема `agg` рисует
  «обычный» цвет текста (у demo-magic это `BOLD`/`GREY` без явного цвета) чёрным
  на чёрном фоне → чёрный экран. Решение — задать светлую тему:
  `AGG_OPTS="--theme=solarized-light"`. По умолчанию `record-demo.sh` и `make record`
  уже используют `--theme=solarized-light`, переопределить можно через `AGG_OPTS`
  (значение подставляется целиком, например `--theme=solarized-dark`). Доступные
  темы и имена флагов зависят от версии `agg` — смотрите `agg --help`
  (в некоторых сборках нет `tango`; fps-флаг называется `--fps` или `--fps-cap`).
- **`pv: command not found`** — установите `brew install pv` (или запустите
  demo-скрипт с `unset TYPE_SPEED`, чтобы отключить имитацию печати).
- **Запись пустая/мгновенная** — проверьте, что `-w` передан (`-w 1`), иначе
  demo-magic будет ждать нажатия Enter, а в неинтерактивном TTY это завершится
  сразу. Используйте `record-demo.sh` (он добавляет `-w` сам).
- **agg не умеет `.mp4`** — используйте `.webm` либо поставьте `agg` версии с
  поддержкой MP4 (`go install github.com/asciinema/agg@latest`).
