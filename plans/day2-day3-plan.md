# План: Day 02 (формат ответа) и Day 03 (способы рассуждения)

Оба дня — консольные Go-приложения, повторяющие стиль `day_01`:
автономный Go-модуль (только стандартная библиотека), OpenAI-совместимый
endpoint `/chat/completions`, настройки из `.env` (`LLM_API_KEY`,
`LLM_BASE_URL`, `LLM_MODEL`), приём запроса из аргумента CLI или интерактивно,
плюс `demo/demo.sh` и `Makefile`. Демо-видео **не** записываем.

Общая структурирующая задача для обоих дней — **определить песню по подсказке
и вернуть: название, исполнитель, жанр, год выхода**.

## Day 02 — Контроль формата ответа

Цель: один и тот же запрос, но с разным уровнем управления ответом
(формат, длина, условие завершения). Сравнить «без ограничений» и «с ограничениями».

### Структура `day_02/`

| Файл          | Назначение                                                            |
|---------------|-----------------------------------------------------------------------|
| `main.go`     | Клиент + флаги `--free`, `--limited`, `--run-all`, сравнение          |
| `go.mod`      | Модуль `day_02`                                                        |
| `Makefile`    | Цели `run-free`, `run-limited`, `run-all`, `build`                     |
| `README.md`   | Описание, переменные, примеры                                          |
| `.gitignore`  | Защита `.env` и бинарников                                             |
| `demo/demo.sh`| Демо через demo-magic (без записи видео)                               |

### Промпты

Базовый запрос (предзаданный текст по умолчанию, переопределяется аргументом):

> «Найди песню по подсказке: <hint>. Верни название, исполнителя, жанр и год выхода.»

**`--free`** — отправляем ровно этот запрос, без доп. инструкций.
Сервер получает обычный запрос (без `max_tokens`, `stop`, `response_format`).

**`--limited`** — тот же запрос, но к нему добавляются **три уровня контроля**:

1. **Явный формат ответа** — инструкция в промпте + `response_format`:
   `{"type": "json_object"}` и требование «ответь строго JSON с полями
   song, artist, genre, year».
2. **Ограничение длины** — `max_tokens: 120` в теле запроса + инструкция
   «не более 40 слов».
3. **Условие завершения** — `stop: ["</output>"]` + инструкция «заверши ответ
   маркером </output>».

В структуру `chatRequest` добавляются опциональные поля
`MaxTokens *int`, `Stop []string`, `ResponseFormat *respFormat`
(используем указатели, чтобы сериализовать их только при необходимости).

**`--run-all`** — запускает `--free` и `--limited` последовательно, печатает
каждый ответ с заголовком, затем сводную таблицу-сравнение:

- длина ответа (в токенах/символах)
- распарсился ли JSON корректно
- согласованность значений song/artist/genre/year
- наличие маркера `</output>` / обрезание по `stop`

### Makefile

```make
run-free:      go run . --free
run-limited:   go run . --limited
run-all:       go run . --run-all
build:         go build -o llm_client .
```

## Day 03 — Разные способы рассуждения

Цель: одна логическая/аналитическая задача решается через API четырьмя
способами, результаты сравниваются (отличаются ли, какой точнее).

Задача — аналитическая, та же тема песен:
> «По описанию найди песню: „…цитата/факты…“. Обоснуй выбор: название,
> исполнитель, жанр, год выхода.»

### Структура `day_03/`

Та же, что у `day_02/`.

### Четыре стратегии (флаги)

| Флаг            | Стратегия                                                                                       |
|-----------------|-------------------------------------------------------------------------------------------------|
| `--direct`      | Прямой ответ: отправляем задачу как есть, без доп. инструкций.                                  |
| `--step`        | Добавляем «Решай пошагово, объясняй каждый шаг».                                                 |
| `--prompt-gen`  | Модель сначала пишет промпт для решения задачи (chain №1), затем этот промпт отправляем как запрос (chain №2). |
| `--panel`       | Группа экспертов: аналитик, инженер, критик. Каждый — отдельное системное сообщение в диалоге; получаем решение каждого. |
| `--run-all`     | Запускает все четыре, печатает каждое решение, затем сравнение по полноте/точности/прозрачности. |

### Реализация стратегий

- `--direct` / `--step`: обычный однопользовательский запрос; разница — в тексте промпта.
- `--prompt-gen`: два вызова API. Первый: «Составь подробный промпт, который
  решит задачу X». Берём `content` первого ответа и отправляем его как
  `user`-сообщение во втором вызове.
- `--panel`: мультисообщение `messages`:
  1. `system` = «Ты — аналитик...»
  2. `system` = «Ты — инженер...»
  3. `system` = «Ты — критик...»
  4. `user` = задача.
  Один запрос, вывод каждого ролевого блока отдельно (парсим по ролям через
  разделители в промпте, т.к. model возвращает единый текст).

### Сравнение в `--run-all`

Для каждой стратегии фиксируем:
- корректен ли ответ (совпадают ли песня/исполнитель/жанр/год),
- полнота (все 4 поля),
- прозрачность рассуждений (есть ли пошаговое обоснование),
- выводим вердикт «какой способ дал наиболее точный результат».

## Общие решения

- Клиент и хелперы (`loadEnv`, `fatal`, вызов `/chat/completions`) дублируются
  в каждый день автономно — как в `day_01`, без внешних зависимостей и shared-пакетов.
- `.env` создаём рядом (ключ подставляет пользователь), в git не коммитим.
- `demo/demo.sh` — через demo-magic, без `set -e`, со ссылкой «см. skill record-demo»
  (правило AGENTS.md). Запись видео не запускаем.
- В корневом `README.md` добавляем упоминание `day_02` и `day_03`.
