# Day 03 — Разные способы рассуждения (параллельно + отчёт)

Программа на **Go** (только стандартная библиотека), которая решает **одну и ту же
математическую задачу** через OpenAI-совместимый API несколькими способами,
запускает их **последовательно с интерактивным прогрессом** в терминале,
сохраняет каждый ответ в **JSON** и детальный вывод в **лог-файлы**, а затем
строит по результатам статистику/сравнение.

Задача по умолчанию — комбинаторная задача про напитки в кафе:

> В кафе три вида напитков: кофе (200 ₽), чай (150 ₽) и какао (180 ₽). Клиент хочет
> купить ровно 5 напитков на общую сумму 900 ₽. Сколько чашек каждого напитка он
> мог купить? Перечисли все возможные комбинации.

Верный ответ — **две** комбинации:

1. кофе 0, чай 0, какао 5 → 5·180 = 900 ₽;
2. кофе 3, чай 2, какао 0 → 3·200 + 2·150 = 600 + 300 = 900 ₽.

## Как устроено

Каждый способ рассуждения — **отдельная команда и отдельный `.go` файл**.
Результат пишется в `results/<метод>.json`, детальный вывод — в `logs/<метод>.log`.
Команда `run-all` запускает все способы последовательно и показывает
**интерактивную панель прогресса** в терминале (статус каждого метода обновляется
по ходу выполнения). Команда `report` читает JSON и строит сравнение/статистику.

| Подкоманда      | Что делает                                                                  |
|-----------------|-----------------------------------------------------------------------------|
| `direct`        | Прямой ответ без доп. инструкций → `results/direct.json`                    |
| `step`          | «Решай пошагово» → `results/step.json`                                      |
| `prompt-gen`    | Модель сама составляет промпт, затем решает по нему → `results/prompt-gen.json` |
| `panel`         | Эксперты с **последовательной передачей** задачи между ролями → `results/panel.json` |
| `run-all`       | Последовательный запуск всех стратегий с интерактивным прогрессом           |
| `report`        | Сравнение и статистика по собранным `results/*.json`                        |

Детали каждого метода (промпты, ответы модели) не засоряют терминал при `run-all` —
они накапливаются в отдельных лог-файлах `logs/<метод>.log`, а в терминале
обновляется компактная панель статусов (○ ожидание / ● выполняется / ✓ готово / ✗ ошибка).

## Панель экспертов (последовательная передача)

Каждый эксперт делает **ровно одну итерацию отдельным запросом**, и ответ
предыдущего дополняет запрос к следующему. Затем координатор сводит итог:

1. **Математик** — записывает систему уравнений и неравенств, определяет границы перебора, доказывает отсутствие решений вне них;
2. **Программист** — описывает алгоритм перебора как код (циклы, условия, проверки), прогоняет мысленно и выписывает все прошедшие проверку комбинации;
3. **Ревизор** — подставляет каждую комбинацию обратно (5 напитков, 900 ₽, целые неотрицательные), отмечает лишние и добавляет пропущенные;
4. **Координатор** — выводит итоговый список всех проверенных комбинаций в формате `(кофе, чай, какао)`.

В консоли секции `— Математик —`, `— Программист —`, `— Ревизор —`, `— ИТОГОВЫЙ СПИСОК —`;
детали диалога накапливаются в `logs/panel.log`.

## Структура папки

| Файл            | Назначение                                                       |
|-----------------|------------------------------------------------------------------|
| `main.go`       | Точка входа: диспетчеризация по подкоманде                        |
| `task.go`       | `defaultTask` (задача про напитки)                               |
| `result.go`     | `Result`-структура + запись/чтение JSON + парсер/проверка комбинаций |
| `reporter.go`   | Интерактивный прогресс в терминале + запись деталей в `logs/`     |
| `runner.go`     | `run-all`: последовательный запуск всех стратегий                |
| `direct.go`     | Стратегия «прямой ответ»                                         |
| `step.go`       | Стратегия «пошаговое решение»                                    |
| `promptgen.go`  | Стратегия «модель составляет промпт»                             |
| `panel.go`      | Панель экспертов (последовательная передача)                     |
| `report.go`     | Отчёт/сравнение по `results/*.json`                              |
| `parse_test.go` | Юнит-тесты парсера комбинаций                                    |
| `Makefile`      | Цели для каждой стратегии, `run-all`, `report`                   |
| `results/`      | JSON-файлы результатов (**в git не хранятся**)                   |
| `logs/`         | Детальные логи по каждому методу (**в git не хранятся**)         |

## Запуск

```bash
cd day_03

# Одна стратегия (пишет свой JSON)
make run-direct       # или go run . direct
make run-step         # или go run . step
make run-prompt-gen   # или go run . prompt-gen
make run-panel        # или go run . panel

# Все четыре последовательно с интерактивным прогрессом, затем:
make run-all          # панель статусов в терминале, детали в logs/
make report           # отчёт/статистика по results/*.json

# Посмотреть детали конкретного метода:
cat logs/direct.log
```
