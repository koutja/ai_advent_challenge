# FAQ: продукт «AI Advent Challenge агент»

Вопросы и ответы о продукте для ассистента поддержки. Источник для RAG:
индекс `index_service` сканирует весь репозиторий, поэтому после
`cd index_service && make index` этот файл попадает в корпус.

## Авторизация и API-ключи

### Почему не работает авторизация / ошибка 401?
Ключ API читается из переменной окружения `LLM_API_KEY` (каскадом: окружение →
`day_NN/.env` → корневой `/.env` → дефолты). Ошибка 401 означает, что ключ
не задан, неверен или не подхватился. Проверьте:
1. Есть ли корневой `/.env` с `LLM_API_KEY` (файл в `.gitignore`, в git не хранится);
2. Не перекрывает ли локальный `day_NN/.env` корневой;
3. Перезапустите процесс после правки `.env` — переменные читаются при старте.

### Какие переменные окружения нужны для работы?
`LLM_API_KEY` (ключ), `LLM_BASE_URL` (эндпоинт, по умолчанию `api.openai.com`),
`LLM_MODEL` (модель). Все три читаются общим пакетом `llm` через `llm.New()`.

## Подключение пакета llm

### Как подключить общий пакет llm к новому дню?
В `go.mod` дня добавьте:
```
require aichallenge/llm v0.0.0
replace aichallenge/llm => ../llm
```
В коде используйте только `llm.New()` + `client.Chat(...)` — HTTP/JSON/loadEnv
дублировать не нужно.

## RAG

### Как работает RAG в агенте?
Вопрос → ретрив чанков из индекса `index_service` (семантический поиск через
микросервис `serve.py`, fallback — ключевой поиск по `chunks.jsonl`) → контекст
с источниками → ответ LLM со ссылками `[1]…[n]`.

### Почему RAG не находит документы?
Индекс строится командой `cd index_service && make index` (сканирует весь
репозиторий: README, docs, код). Если документ добавлен после последней
индексации — пересоберите индекс. Для семантического движка нужен запущенный
микросервис: `cd index_service && make serve`.

## MCP

### Что такое MCP и какие инструменты есть?
Model Context Protocol — стандарт подключения инструментов к агенту. Сервер
`bin/mcp-server` обслуживает домены: `tasks` (задачи), `scheduler`
(напоминания/сбор данных), `knowledge` (поиск/сводки), `git` (ветка/статус/diff),
`support` (пользователи и тикеты поддержки). Список инструментов:
`go run ./cmd/cli --mcp-tools`.

### Как вызвать MCP-инструмент вручную?
`go run ./cmd/cli --mcp-call <имя> --mcp-args '{"...":"..."}'`, например
`--mcp-call get_ticket --mcp-args '{"ticket_id":"T-001"}'`.

## Web-чат

### Как запустить web-чат?
`cd agent && go run ./cmd/web` — откроется `http://127.0.0.1:8080`. Остановка:
`make stop-web`. Web и CLI вызывают одно и то же ядро `Agent`.

## Локальная LLM

### Можно ли работать без облачного API?
Да: локальная модель через Ollama (`qwen2.5:0.5b`). В `.env` укажите
`LLM_BASE_URL=http://localhost:11434/v1`, `LLM_MODEL=qwen2.5:0.5b`,
`LLM_API_KEY=ollama`. Запуск: `make run-local` в `agent/`.

## Поддержка и тикеты

### Как создать тикет поддержки?
Через MCP-инструмент `create_ticket` (домен `support`): укажите существующего
пользователя (`user_id`), тему и текст обращения. Тикет сохраняется в JSON-CRM
(`results/support_crm.json`) и переживает рестарты.

### Как ассистент учитывает контекст тикета?
Команда `--support "<вопрос>" --ticket <id>` берёт тикет и данные пользователя
через MCP `get_ticket`, подмешивает их в промпт и отвечает с учётом плана,
статуса и истории обращения.
