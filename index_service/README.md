# index_service — Индексация документов и RAG-микросервис поиска

> Переименован из day_21: папка теперь не только строит индекс документов,
> но и отдаёт его наружу через HTTP-микросервис (`serve.py`), к которому
> обращается агент (см. `agent/feature/rag`) для RAG-запросов.

Локальный пайплайн индексации документов: **разбиение на чанки → эмбеддинги →
векторный индекс (FAISS) → семантический поиск**. Плюс сравнение двух стратегий
чанкинга с retrieval-оценкой.

Стек — **Python** (в отличие от Go-дней): задача RAG-пайплайна, и здесь зоопарк
инструментов (sentence-transformers, faiss-cpu, pypdf) заметно удобнее, чем в Go.
Эмбеддинги **локальные** — офлайн, бесплатно, API-ключ не нужен.

## Что делает

1. Сканирует папку с документами (по умолчанию — весь репозиторий) и извлекает
   текст: `.md/.txt`, код (`.go/.py/.js/...`), PDF (через pypdf).
2. Разбивает документы на чанки **двумя стратегиями**:
   - `fixed` — скользящее окно фиксированного размера с перекрытием;
   - `structure` — по структуре: секции markdown-заголовков, топ-уровневые
     объявления кода (`func`/`type`/`def`/`class`), страницы PDF; мелкие соседние
     блоки склеиваются, преамбула файла не теряется.
3. Считает эмбеддинги локальной моделью `intfloat/multilingual-e5-small`
   (384-мерные векторы, русский+английский; первый запуск скачивает модель
   ~470 МБ с Hugging Face, дальше — офлайн).
4. Сохраняет индекс для каждой стратегии: **FAISS** (`vectors.faiss`) +
   метаданные и текст чанков (`chunks.jsonl`) + параметры (`meta.json`).
5. Умеет искать по индексу (топ-k с метаданными и сниппетами) и сравнивать
   стратегии: метрики чанков + retrieval-оценка по «золотым» запросам.

Каждый чанк несёт метаданные: `source`, `title`, `section`, `chunk_id`,
`format`, диапазон символов в исходнике, стратегия.

## Инструменты на Mac

| Что | Зачем | Установка |
|-----|-------|-----------|
| Python 3.10+ (рекомендуется 3.11/3.12) | рантайм | `brew install python@3.12` (если `python3` старый) |
| pip + venv | изолированное окружение | идут с Python |
| пакеты из `requirements.txt` | sentence-transformers, torch, faiss-cpu, numpy, pypdf, pytest | автоматически через `make setup` |
| Интернет (один раз) | модель эмбеддингов ~470 МБ | при первом запуске |

Никаких системных зависимостей (Xcode CLT и т.п.) не требуется. `LLM_API_KEY` не нужен.

## Запуск

```bash
cd index_service

make setup          # создать .venv и установить зависимости (один раз)

# Быстрая отладка: один корневой README.md репозитория
make index-debug

# Полная индексация документов репозитория (обе стратегии)
make index          # = python main.py index --docs ../

# Поиск по готовому индексу
make query QUERY="как подключить пакет llm"
make query QUERY="тиры моделей weak medium strong в day_05"

# Сравнение стратегий + отчёт в results/chunking_comparison.md
make compare

# Полный прогон: index → compare → пример поиска
make run-all

# Юнит-тесты чанкеров
make test

# Своя папка с документами (или один файл)
python main.py index --docs ../plans
python main.py query "план развития агента" --strategy structure

# HTTP-микросервис доступа к индексу (порт переопределяется: make serve PORT=9000)
make serve
```

> `--docs` может указывать на папку или на один файл. Если `docs_dir` в
> `config.json` пуст и `--docs` не задан — берётся корневой `README.md` (отладка).

## Микросервис доступа к индексу (`serve.py`)

Папка выполняет роль **сервиса индексации**: кроме построения индекса, она
отдаёт его наружу по HTTP — к нему обращается агент
([`agent/feature/rag`](../agent/feature/rag)) для RAG-запросов.

Эндпоинты (только стандартная библиотека Python, переиспользуются модули папки):

| Эндпоинт | Назначение |
|----------|------------|
| `GET /health` | статус: индекс, стратегия, число чанков, движок |
| `POST /search` | тело `{"query": "...", "top_k": 5}` → top-k чанков с метаданными (`source`, `section`, `chunk_id`, `score`) и полным текстом |

```bash
make serve                                    # http://127.0.0.1:8734
curl -s http://127.0.0.1:8734/health
curl -s -X POST http://127.0.0.1:8734/search \
     -H 'Content-Type: application/json' \
     -d '{"query":"как подключить пакет llm","top_k":3}'
```

Агент при недоступности сервиса автоматически переключается на ключевой поиск
прямо по `chunks.jsonl` — RAG продолжает работать офлайн.

## Переменные окружения

Не требуются. Эмбеддинги локальные; конфигурация — в `config.json`
(модель, размеры чанков, batch_size, топ-k). При желании поменять модель,
например, на `paraphrase-multilingual-MiniLM-L12-v2`, — обновите `embed.model`
и поставьте `embed.use_prefixes: false` (e5-префиксы нужны только e5-семейству).

## Пример вывода (сравнение стратегий)

Корпус: 135 документов, ≈282 стр. текста (README/планы/код репозитория).

| Метрика | fixed | structure |
|---|---|---|
| Чанков | 442 | 822 |
| Средний размер, симв. | 1736 | 865 |
| «Мусорные» чанки (<120 симв.) | 5 (1.1%) | 64 (7.8%) |
| Покрытие текста | 100% | 100% |
| Дублирование (перекрытие) | 1.087 | 1.007 |
| Recall@5 (6 золотых запросов) | 0.833 | **1.0** |
| MRR | 0.667 | **0.694** |

**Вывод:** `structure` точнее находит ответ (recall@5 = 1.0, выше MRR) и даёт
осмысленные границы чанков с метаданными секций, но порождает больше мелких
чанков. `fixed` — проще, компактнее, но «разрезает» смысловые блоки и дублирует
текст из-за перекрытия окон (в 1.09 раза больше суммарного объёма). Для RAG
рекомендуется `structure`; `fixed` хорош как детерминированный baseline.

Полный отчёт (метрики + результаты по каждому запросу) генерируется в
`results/chunking_comparison.md`.

## Замечания

- Пайплайн использует только стандартную библиотеку + перечисленные пакеты;
  к Go-пакету `llm` этот день не подключён — локальным эмбеддингам API не нужен.
- Если `faiss-cpu` не установится под вашу версию Python — поиск автоматически
  перейдёт на numpy-режим (формат индекса тот же).
- `index/`, `results/`, `logs/`, `.venv/` — генерируемые артефакты, в git не
  коммитятся (см. `.gitignore`).
- Демонстрацию дня записываете сами — простой записью видео в среде разработки.
