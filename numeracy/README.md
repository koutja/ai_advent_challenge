# numeracy — тренажёр количественной грамотности

Реальная задача: тренировка умения замечать манипуляции статистикой и числами.
Количественная грамотность помогает не поддаваться на «продажи выросли на 200%»
(при базе в 1 товар), «тест точный на 99%» (при редкой болезни) и «миллионы
потрачены» (без перевода в понятные метрики).

## Как AI участвует (задачи — не хардкод)

Flow: **AI генерирует задачу → сохраняет в SQLite → пользователь отвечает →
проверка → объяснение**. Задачи НЕ зашиты в код: генератор — LLM, хранилище —
SQLite ([`store.go`](store.go), таблица `tasks`).

- **Сначала генерация** ([`generate.go`](generate.go)): LLM сочиняет новую
  задачу (вопрос, правильный ответ, варианты, объяснение) и возвращает JSON
  `{category, level, kind, unit, expected, tolerance, question, options,
  correct_idx, explanation}`. Задача проходит структурную валидацию и
  **самопроверку** (второй вызов LLM: решает свою же задачу; при расхождении
  с `expected` задача отклоняется — в логах `[генерация] отклонено: …`).
  Только после этого сохраняется в базу (`results/numeracy.db`, источник
  `generated`).
- **Если генерация не произошла** (нет LLM / невалидный JSON) — задача берётся
  из базы: предпочтительно ранее сгенерированные, иначе базовые (`seeds/tasks.json`,
  источник `seed`). В логах/листе это отражается явно:
  `[генерация] НОВАЯ задача ... сохранена в базу (id=..)` либо
  `[база] задача взята из базы (id=.., источник=seed)`.
- **Базовые задачи** — это данные ([`seeds/tasks.json`](seeds/tasks.json)), а не
  код; загружаются в SQLite при первом запуске (пустая таблица) и математически
  проверены.
- **AI объясняет** ([`explain.go`](explain.go)): после ответа LLM разбирает,
  почему ответ верный (или нет) и в чём ловушка/манипуляция. Без ключа —
  сохранённое при создании задачи объяснение.

> ⚠️ AI-генерация может содержать математические ошибки (зависит от модели):
> источник задачи всегда виден в логах (`generated`/`seed`). Для точных данных
> используйте seed-задачи или модель покрупнее; сброс базы — удалить
> `results/numeracy.db` (задачи перегенерируются/берутся из seed).

## Категории

| Категория | Что тренирует | Пример |
|-----------|---------------|--------|
| `percent` | проценты и доли: «процент от процента», смена базы, абсолютный vs относительный прирост | «Продажи выросли на 200%, но база была 1 товар — сколько стало?» |
| `probability` | сначала простое — классическая вероятность (кубик, монеты, шарики, билеты, дождь, карты); уровень `hard` — условная вероятность | easy: «Вероятность шестёрки на кубике?» / hard: «Тест точен на 99%, болезнь у 1% — вероятность болезни при положительном результате?» |
| `scale` | порядки величин: сколько зарплат/вагонов/километров в «громком» числе (MC) | «1 000 000 км оптоволокна — сколько раз вокруг Земли?» |

## Запуск

```bash
cd numeracy

make run              # REPL по всем категориям (по умолчанию)
make run-percent      # REPL по процентам
make run-probability  # REPL по вероятностям (все уровни)
make run-probability-easy  # вероятности только easy: кубик/монеты/шарики/билеты/дождь/карты
make run-scale        # REPL по порядкам величин
make run-easy         # все категории, только лёгкий уровень
make run-sheet N=3 CATEGORY=all   # лист задач с ответами и объяснениями → results/worksheet_<cat>.md

make build            # собрать в bin/numeracy
make test             # тесты
```
Сложность задаётся флагом `--level easy|hard|all` (по умолчанию `all`); лёгкий уровень
probability — классическая вероятность без условных (Байес/Монти Холл — hard):
```bash
go run . --category probability --level easy  # только простые вероятности
go run . --sheet 5 --category probability --level easy
```

REPL-команды: `/stop` — выход (итог + лог в `results/`), `/skip` — пропустить,
`/category <имя>` — сменить категорию. Для вариантов ответа вводите номер
(1/2/3) или текст варианта; числовые ответы — с допуском и дробями (`1/6`, `17%`).

Настройки LLM — как у всех дней: `.env` (каскад: локальный → корневой),
переменные `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL`. Без ключа тренажёр
работает в режиме встроенных шаблонов (без AI-формулировок и объяснений).

## Структура

| Файл | Назначение |
|------|------------|
| [`task.go`](task.go) | типы задачи/категорий/уровня + структурная валидация |
| [`generate.go`](generate.go) | AI-генерация задачи (JSON) + валидация результата |
| [`store.go`](store.go) | SQLite-хранилище (`tasks`), загрузка seed при первом запуске |
| [`seeds/tasks.json`](seeds/tasks.json) | базовые (проверенные) задачи — ДАННЫЕ, не код |
| [`check.go`](check.go) | проверка ответов по задаче (допуск, дроби, MC) |
| [`explain.go`](explain.go) | AI-объяснение ловушки + сохранённое объяснение задачи |
| [`main.go`](main.go) | REPL и batch (`--sheet`), поток «генерация → база» |
| `results/` | база `numeracy.db`, листы и логи сессий (**в .gitignore**) |

Путь к базе задаётся флагом `--db` (по умолчанию `results/numeracy.db`); сброс —
удалить файл базы.
