# Universal Rules (загружается в каждый чат)

Этот файл — единый источник обязательных правил для работы в этом репозитории.
Он автоматически попадает в контекст каждого чата/агента. Не дублируй его содержимое
в других файлах (README, demo.sh и т.д.) — за справкой обращайся сюда или в skill.

## Проект

- Ежедневные консольные проекты в папках `day_NN/` (Go и др.). В каждом дне: код,
  `Makefile`, `README.md`.
- Исходники скиллов лежат в `.agents/skills/<name>/`. Это универсальный fallback:
  многие harness (OpenCode, Claude, ...) читают `.agents/skills/` автоматически.

## Запись демонстрации в видео (MP4)

Цель — показать прогон консольного проекта в видео, **без ручной записи экрана**.
Пайплайн: `demo-magic.sh` (печатает команды с задержкой) → `asciinema rec` (`.cast`)
→ `agg` (рендер в `.mp4`).

Быстрые команды (подробности и функции demo-magic — в skill `record-demo`):

```bash
make sync                        # симлинк на скиллы из .agents/skills в активную harness
make install-tools               # один раз: asciinema, agg, ffmpeg, pv
make new-demo DAY=day_01         # создать day_01/demo/demo.sh из шаблона
make record DEMO=day_01/demo/demo.sh   # записать и отрендерить day_01/demo/demo.mp4
```

Варианты: `make sync HARNESS=claude|roo|cursor`, `OUT=...webm`, `AGG_OPTS="..."`,
`KEEP_CAST=1`.

## Обязательные правила

1. **За справкой — в skill, не в код.** Не размещай большие блоки-шпаргалки
   (таблицы команд demo-magic, переменные и т.п.) внутри `demo.sh`, шаблонов или
   README. Достаточно короткого комментария «см. skill record-demo» / «см. AGENTS.md».
2. **Не используй `set -e` в demo-скриптах.** Ошибка одной команды (например
   `go run` без API-ключа) оборвала бы запись. Демо должно идти до конца.
3. **По завершении задания обновляй корневой `README.md`:** секция
   «Запись демонстрации» должна содержать актуальные команды записи, чтобы их не
   приходилось вспоминать. Если секции нет — создай, если команды изменились —
   приведи к актуальному виду.
4. **Гигиена git.** Не коммить генерируемые артефакты: `**/demo/*.cast`,
  `**/demo/*.{mp4,webm,gif}` и копию скилов `.codeassistant/` (уже в `.gitignore`).
  Исходник `day_01/demo/demo.sh` и `.agents/skills/` — коммить.
5. **Оформление `SKILL.md`.** В frontmatter всегда оборачивай значение `description:`
  в двойные кавычки (`description: "..."`). Если в описании есть двоеточия, скобки,
  спецсимволы или оно длинное — без кавычек YAML парсится неверно, и скилл может
  не распознаться harness'ом (не попасть в `available_skills`).

## Источники информации (по приоритету)

1. `AGENTS.md` (этот файл) — универсальные правила.
2. `.agents/skills/record-demo/SKILL.md` — подробная инструкция записи демо.
3. Корневой `Makefile` — команды sync/new-demo/record/install-tools.
