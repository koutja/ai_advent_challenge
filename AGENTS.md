# Universal Rules (загружается в каждый чат)

Этот файл — единый источник обязательных правил для работы в этом репозитории.
Он автоматически попадает в контекст каждого чата/агента. Не дублируй его содержимое
в других файлах (README и т.д.) — за справкой обращайся сюда или в skill.

## Проект

- Ежедневные консольные проекты в папках `day_NN/` (Go и др.). В каждом дне: код,
  `Makefile`, `README.md`.
- Исходники скиллов лежат в `.agents/skills/<name>/`. Это универсальный fallback:
  многие harness (OpenCode, Claude, ...) читают `.agents/skills/` автоматически.
- Демонстрацию работы дня записывает пользователь сам — простой записью видео
  через среду разработки. Агент не создаёт demo-скриптов и не запускает запись.

## Обязательные правила

1. **За справкой — в skill, не в код.** Не размещай большие блоки-шпаргалки
   внутри README, шаблонов или кода. Достаточно короткого комментария со ссылкой
   на skill или `AGENTS.md`.
2. **Гигиена git.** Не коммить генерируемые артефакты (бинарники, логи, SQLite-базы)
   и копию скилов `.codeassistant/` (уже в `.gitignore`). Исходники `.agents/skills/`
   и код дней — коммить.
3. **Оформление `SKILL.md`.** В frontmatter всегда оборачивай значение `description:`
   в двойные кавычки (`description: "..."`). Если в описании есть двоеточия, скобки,
   спецсимволы или оно длинное — без кавычек YAML парсится неверно, и скилл может
   не распознаться harness'ом (не попасть в `available_skills`).
4. **Конфигурация LLM — единый способ.** Не выдумывай свои поля для endpoint/ключа/модели.
   Секреты и подключение берутся из переменных окружения через общий пакет `llm`
   (каскадная загрузка `.env`: текущая папка → корень репозитория). В `config.json`
   указываются **имена** этих переменных, а не значения:
   - `LLM_API_KEY` — API-ключ (в конфиг сам ключ никогда не кладём);
   - `LLM_BASE_URL` — базовый URL эндпоинта;
   - `LLM_MODEL` — модель.
   Прямых полей с URL/ключом/моделью в конфиге не добавляем. Загружать настройки —
   через `llm.LoadEnvCascade()` + `llm.NewWithConfig(...)` (или `llm.New()`).

## Источники информации (по приоритету)

1. `AGENTS.md` (этот файл) — универсальные правила.
2. `.agents/skills/create-day/SKILL.md` — каркас нового дня.
3. Корневой `Makefile` — команды sync / new-day.
